# Point-in-Time Walk-Forward Hindcast Methodology for the Portfolio Advisory Engine (1-year forward verification)

Scope note: these notes cover how to design a rigorous hindcast of `signal_engine.evaluate_signal` decisions (SELL / TRIM / ACCUMULATE / BUY / HOLD / REVIEW, plus NO DATA / VERIFY DATA / NO THESIS) on monthly decision dates Oct 2023 to Oct 2025, each scored 252 trading days later against Nifty 50. Costs and taxes are excluded. Web access was partly restricted: Wikipedia, NBER and Quantpedia pages could not be fetched (DNS failure), so some citations rely on search-result abstracts or summaries rather than full text. These are flagged where it matters.

Repo facts used below (from reading `/home/user/Portfolio/signal_engine.py` and `thesis.csv`, not web sources):
- Decision tree order: no technical data, then NO THESIS, then thesis INVALIDATED (price <= Invalidation_Price) gives SELL; BEARISH (price < 200-DMA) + total_return < 0 + (conviction < 4 or thesis not intact) gives SELL; trailing stop hit (price < max(invalidation, 52w-high minus k*ATR)) gives TRIM; overextended (price > 50-DMA * overextension_multiple), position weight > max_position_pct (8%), or sector/risk-group cap breach for a major holding gives TRIM; intact thesis + conviction >= 4 + under caps + (BULLISH, or BEARISH with total_return > 25%) gives ACCUMULATE (BUY if weight == 0); everything else is HOLD.
- `total_return` is return vs the user's own cost basis, so decisions depend on purchase history (trades.csv), not just market data.
- `thesis.csv` rows carry `Last_Updated = 2026-09-26`, so the Invalidation_Price and Conviction values were set after every planned decision date. They are not point-in-time.
- The "REVIEW" signal comes from `fundamental_unknown` (ROE missing); the decision field still resolves to HOLD/TRIM/etc. The hindcast must score the `decision` field, not the emoji `signal`.

## 1. Defining "correct" per decision type at a 1-year horizon (excess-return definition, neutral band, benchmark choice)

### Takeaway
Score each decision on the 252-trading-day excess return of the stock over a dividend-inclusive benchmark (Nifty 50 TRI, or an ETF adjusted close as a proxy), use a symmetric neutral band, and treat HOLD as an "inconclusive by design" class scored only by magnitude (|excess| within band), not by direction. Using the Nifty 50 price index while stocks are measured on adjusted (dividend-inclusive) prices biases every stock toward "outperformance" by roughly the index dividend yield (about 1 to 1.4 percentage points a year).

### Cited Findings
- NSE publishes Nifty 50 variants including the Nifty 50 Total Returns Index (Gross and Net) and a Dividend Points Index alongside the price index — [NSE Nifty 50 factsheet](https://www.niftyindices.com/Factsheet//ind_nifty50.pdf); [NSE archive factsheet](https://archives.nseindia.com/content/indices/ind_nifty50.pdf)
- A Total Return Index includes both price movement and reinvested dividends; a Price Return index measures only price change — [Bajaj AMC, Nifty 50 dividend yield](https://www.bajajamc.com/knowledge-centre/nifty-50-dividend-yield)
- NSE also launched a Nifty 50 Net Total Return index that reinvests dividends after relevant taxes (withholding) — [5paisa, NSE launches NIFTY50 NTR](https://5paisa.com/news/nse-launches-nifty50-net-total-return-ntr-index). Since the test excludes tax, the Gross TRI is the matching benchmark.
- TRI exceeds the price index over time by roughly the index's dividend yield, and comparing against a price index overstates outperformance by that yield — [m.Stock, TRI vs price index](https://www.mstock.com/articles/total-return-index-vs-price-index); [NISM V-A study guide](https://open-exam-prep.com/study-guides/nism-series-v-a/mutual-fund-scheme-performance/price-return-index-or-total-return-index)
- Observed 1-year TRI-minus-PRI gaps vary by window (one snapshot showed about 0.7 points, another about 0.1 points), so the gap is noisy over single years — [Bajaj Finserv, TRI](https://www.bajajfinserv.in/investments/total-return-index-in-mutual-fund); [multibagg Nifty indices 1-yr](https://www.multibagg.ai/market-pulse/articles/nifty-indices-one-year-returns-cmrl5lgvd01rkqt0jigwke0zs). Treat these as indicative; they are secondary sources.
- I found no primary NSE methodology text in this session on exact ex-date reinvestment rules for the TRI; one secondary source says dividends are treated as reinvested after the close of the ex-date (search-result summary, not verified).

### Inferences
- **Benchmark rule:** Benchmark = Nifty 50 TRI (gross). If TRI history is not available in the data pipeline, use a liquid Nifty 50 ETF's dividend-adjusted close (e.g. a NIFTYBEES-type ETF via yfinance `Adj Close`/`auto_adjust=True`) and record the tracking error caveat (ETF expense ratio and tracking difference make it lag TRI slightly). Never mix adjusted stock prices with the unadjusted price index. If only the price index is available, stock returns must also be price-only (unadjusted for dividends but adjusted for splits/bonuses). Consistency matters more than which convention.
- **Excess return definition:** Use simple (arithmetic) excess return `XR = (1+R_stock) / (1+R_bench) - 1` (relative wealth ratio) as the primary metric; it equals the log difference `ln(1+R_s) - ln(1+R_b)` after transform, is additive across sub-periods in log form, and is invariant to which leg is larger. Report the plain difference `R_s - R_b` as a secondary column. The two coincide closely at small values; the ratio form avoids exaggeration when the benchmark return is large.
- **Correctness by decision type (directional classes):**
  - SELL: correct if XR < -band; wrong if XR > +band; neutral otherwise.
  - TRIM: same direction as SELL (the reduced weight should have underperformed). Optionally a weaker test: TRIM correct if XR < +band (i.e. the stock did not materially outperform), because TRIM is a risk-control action, not a short call. Preregister which one is primary.
  - ACCUMULATE / BUY: correct if XR > +band; wrong if XR < -band.
  - HOLD: there is no directional claim. Score HOLD two ways and preregister: (a) "HOLD was reasonable" if |XR| <= wider band (e.g. 10%), i.e. no action would have materially helped; (b) report HOLD's excess return distribution as the base rate against which SELL and ACCUMULATE are compared. HOLD should never enter a hit-rate pooled with directional calls.
  - REVIEW signal / NO DATA / VERIFY DATA / NO THESIS: exclude from accuracy statistics, count and report them separately (coverage rate). In the point-in-time run with ROE unavailable historically, REVIEW will fire on almost everything, so ROE gating must be disabled or held constant (see section 4).
- **Neutral band:** A fixed ±2% band is too narrow for 1-year single-stock outcomes in India (single-stock 1-year tracking error vs Nifty is typically far higher than 2%; I found no source quantifying it for this universe, so compute it in-sample). Better: band = ±k * (cross-sectional median 1-year tracking error of the universe), with k preregistered, or report results at ±0%, ±2%, ±5% as a sensitivity table. Preregister one primary band before looking at outcomes.
- **Direction-weighted payoff (preferred over hit rate):** Map decisions to signed scores, e.g. SELL = -2, TRIM = -1, HOLD = 0, ACCUMULATE/BUY = +1, and compute mean signed excess return `score * XR`. This uses magnitudes, not just signs, and feeds directly into the information coefficient (section 2).

## 2. Statistics with overlapping 12-month windows and cross-sectionally correlated stocks

### Takeaway
With ~25 monthly decision dates and a 12-month label horizon, the data contain only about two non-overlapping years of outcomes; nominal counts (~25 dates x ~34 symbols = ~850 decisions) overstate information by an order of magnitude. Inference must be done at the date level (cross-sectional average per date, then time-series inference) with Hansen-Hodrick/Newey-West (lag >= 11 for monthly data) or a block bootstrap over dates with block length ~12, and should be described as exploratory unless effects are large.

### Cited Findings
- Overlapping observations produce strong serial correlation in residuals, and standard errors that ignore this give biased inference — [Britten-Jones et al., overlapping observations, City University](https://openaccess.city.ac.uk/id/eprint/15212/1/JBFA%20Overlapping%20observations%20with%20BrittenJones.pdf)
- Hansen-Hodrick and Newey-West standard errors tend to be severely biased downward when the horizon is long relative to the sample; HH is criticized for poor small-sample performance and severe size distortions for long-run returns (Hodrick 1992; Ang and Bekaert 2001) — [City University paper](https://openaccess.city.ac.uk/id/eprint/15212/1/JBFA%20Overlapping%20observations%20with%20BrittenJones.pdf); [econwpa working paper 0410018](https://econwpa.ub.uni-muenchen.de/econ-wp/fin/papers/0410/0410018.pdf)
- A 2004 working paper argues asymptotically correct standard errors for overlapping regressions can be obtained by multiplying OLS standard errors by sqrt((2/3) * h), where h is the forecast horizon in periods — [econwpa 0410018](https://econwpa.ub.uni-muenchen.de/econ-wp/fin/papers/0410/0410018.pdf) (author not confirmed from search snippet)
- Boudoukh, Israel and Richardson (JFE 2022) derive closed-form small-sample bias of long-horizon estimators and of HH/NW standard errors; small-sample adjustments substantially reduce long-horizon predictability estimates — [NBER w27410](https://nber.org/system/files/working_papers/w27410/w27410.pdf)
- Overlapping data add little information: e.g. 5-year returns over 50 years go from 10 non-overlapping observations to only about 12 effective observations with monthly overlap — [Quantpedia summary, Problems with long-horizon predictability](https://quantpedia.com/problems-with-a-long-horizon-predictability/) (page could not be fetched; claim from search summary)
- Stationary bootstrap (Politis and Romano 1994, JASA 89:1303-1313) resamples blocks of random (geometric) length for weakly dependent stationary data — [UCY repository, The stationary bootstrap](https://gnosis.library.ucy.ac.cy/handle/7/57533); automatic mean block length via Politis-White (2004) with Patton-Politis-White (2009) correction — [R np b.star docs](https://www.rdocumentation.org/packages/np/versions/0.70-5/topics/b.star); [R blocklength package](https://search.r-project.org/CRAN/packages/blocklength/blocklength.pdf)
- Practical heuristic: the sample should contain enough cycles (5-10) for block bootstrap to work; there is no precise multiplier — [SAS blog, stationary bootstrap](https://blogs.sas.com/content/iml/2021/01/20/stationary-bootstrap-sas.html)
- For proportions with small n, Brown, Cai and DasGupta (2001) find the Wald interval's coverage erratic and recommend the Wilson or Jeffreys interval for small n, Agresti-Coull for larger n — [Brown, Cai, DasGupta, Statistical Science](https://projecteuclid.org/euclid.ss/1009213286); [Agresti and Coull 2001](https://users.stat.ufl.edu/~aa/articles/agresti_coull_2001.pdf)
- Example: x=1, n=15 gives Wald [-0.06, 0.19] (impossible negative), Wilson [0.012, 0.30] — [MetricGate comparison](https://metricgate.com/blogs/wilson-vs-agresti-coull-vs-clopper-pearson/) (secondary)

### Inferences
- **Effective sample size, time dimension:** Decision dates Oct 2023 to Oct 2025 span 24 months; with a 12-month label, the number of non-overlapping windows is about 25/12, roughly 2 (plus a partial). Using the sqrt((2/3)h) inflation with h = 12 monthly steps, standard errors are inflated by about sqrt(8), roughly 2.8x, versus naive monthly-iid errors; equivalently the 25 dates carry the information of only about 25/8, roughly 3, independent observations. This is the binding constraint and should be printed in every report.
- **Effective sample size, cross-section:** Stocks on the same date share the market and sector factor. The design effect for an equicorrelated cluster is 1 + (m-1)*rho (Kish design effect; standard survey-sampling result, no web source retrieved this session). With m = 34 and average pairwise excess-return correlation rho = 0.2 to 0.3, the 34 stocks on one date are worth about 34/(1+33*0.25), roughly 4 independent bets. Compute rho empirically from 1-year excess returns.
- **Primary inference unit = the decision date.** For each date t compute a cross-sectional statistic S_t (e.g. mean XR of SELL/TRIM names minus mean XR of ACCUMULATE names, or the Spearman IC). Then test mean(S_t) with Newey-West/HAC using lag L = 11 (h-1) with Bartlett weights, or Hansen-Hodrick (uniform weights, lag 11; can produce a negative variance in small samples, in which case fall back to NW). Also report the stationary/circular block bootstrap over dates with block length 12 (moving-block with 10,000 resamples). With ~25 dates and block 12, the bootstrap has only ~2 blocks of real variation; report it as a sanity check, not as precise inference.
- **Hit-rate intervals:** Wilson intervals assume independent Bernoulli trials. Apply Wilson on an *effective n* (n_eff = n / design_effect_time / design_effect_cross, rounded down), not raw counts, or compute the hit-rate CI by the date-block bootstrap. Report both raw-n Wilson (labelled "naive, overstates precision") and n_eff Wilson.
- **Collapse repeated decisions into episodes:** The same stock will receive the same decision on consecutive months (e.g. ACCUMULATE 9 months running). Define an episode as a maximal run of identical decisions for a symbol; score the episode once, at its first date (entry-based) and optionally at its last date. Report decision-level and episode-level statistics side by side. Episode count is a better proxy for independent calls than decision count.
- **Information coefficient:** Per date, Spearman rank correlation between the signed decision score (SELL -2 ... ACCUMULATE +1, or a finer continuous score such as distance of price from 200-DMA / ATR) and forward 1-year XR. Heavy ties in a 4-level ordinal score make Spearman coarse; also report Kendall tau-b. Report mean IC, IC t-stat with NW lag 11, and fraction of dates with IC > 0. Note IC from adjacent months is ~92% overlapping (11 of 12 months shared), so the 25 monthly ICs are not 25 observations.
- **Minimum sample for any conclusion:** Preregister: no claim of skill unless (a) the effect holds at the episode level, (b) the NW (lag 11) t-stat exceeds 3.0 (Harvey-Liu-Zhu bar, section 5) or the block-bootstrap 95% CI excludes zero, and (c) the decision class has at least ~10 independent episodes across at least 2 non-overlapping years. With this sample, most classes will fail (b); the correct reporting is "insufficient evidence", not "rule works/fails".

## 3. Shadow-portfolio comparison design (follow-model vs do-nothing vs benchmark)

### Takeaway
Run three or four portfolios from the same point-in-time holdings snapshot on the first decision date: (A) follow-model, (B) do-nothing buy-and-hold of the initial holdings, (C) Nifty 50 TRI, and optionally (D) equal-weight rebalance of the same universe. Execute at the next trading day's close after the decision date, hold cash explicitly at a stated rate, and redistribute proceeds by a preregistered rule. Compare CAGR, max drawdown, volatility, turnover and the A-minus-B difference series.

### Cited Findings
- Practitioner backtesting guidance emphasizes look-ahead bias, survivorship bias and execution assumptions as core backtest pitfalls, and recommends DSR/robustness checks — [tradingstrategy.ai backtesting methodology](https://tradingstrategy.ai/docs/learn/backtesting.html)
- I did not retrieve Quantopian lecture or QuantStart pages this session; recommendations below are standard practice rather than citation-backed.

### Inferences
- **Execution:** Decision computed with data up to and including close of date t. Trade at close of t+1 (next trading day) using that day's close; never at t's close (the signal used t's close). Signals on a non-trading day roll to the last trading day on or before the nominal date for computation and to the next trading day for execution.
- **Action sizing (preregistered, mirrors engine semantics):** SELL = sell 100% of position; TRIM = sell 50% (the engine's "sell half" for trailing stop) or sell down to max_position_pct for cap breaches, whichever the engine's rationale specifies; ACCUMULATE = add a fixed tranche (e.g. 1% of portfolio value, capped so weight stays <= max_position_pct) funded from cash only; HOLD = no trade. BUY (weight == 0) only applies if the symbol is in the evaluated universe; with a holdings-only universe it cannot fire.
- **Cash treatment:** Proceeds go to cash earning a stated rate (preregister: 0%, or an Indian liquid-fund/T-bill proxy such as ~6-7% annualized; I did not retrieve a source for the rate, so obtain the series from data). Report results under both 0% and the money-market rate because cash drag is a major driver of "follow-model" underperformance in a rising market. ACCUMULATE draws from cash; if cash is insufficient, scale down pro rata (no leverage, no new external contributions). Alternative variant: SELL proceeds into the benchmark ETF (isolates selection skill from market timing). Preregister one primary variant.
- **No external flows:** The real portfolio had SIP/contributions; the shadow portfolios must exclude them (or apply identical flows to all portfolios on the same dates) so CAGR is comparable.
- **Metrics:** CAGR, annualized volatility, max drawdown and drawdown duration, Sharpe vs cash rate (descriptive only), annual turnover (sum of |trades| / average NAV), number of trades, and the daily return series of A minus B (the active decision value). Inference on A-minus-B uses the same overlap-aware methods as section 2. Report the path chart of all portfolios and the cumulative A/B ratio.
- **Weight inputs to the engine must come from the shadow portfolio itself** (position weight, sector exposure), recomputed each date, so cap-based TRIMs respond to the simulated path, not the real 2026 portfolio. Run a second variant where weights come from the reconstructed real holdings at each date (section 4) and report both.

## 4. Point-in-time rules: invalidation prices, fundamentals, survivorship, corporate actions

### Takeaway
Every input to `evaluate_signal` must be reconstructable as of the decision date. Invalidation prices and conviction set on 2026-09-26 are look-ahead and must either be replaced by a mechanical, preregistered proxy defined from data available at the decision date or disabled (with both runs reported). ROE gating must be disabled because historical fundamentals are not available point-in-time. Using today's 34 holdings as the universe is a selection-biased (survivorship/hindsight) universe; reconstruct holdings from trades.csv at each date.

### Cited Findings
- Look-ahead and survivorship bias are among the primary sources of backtest overstatement; the DSR corrects selection bias across trials but cannot correct biases affecting all configurations uniformly (e.g. survivorship or look-ahead in the data) — [arXiv 2507.07107](https://arxiv.org/pdf/2507.07107); [tradingstrategy.ai](https://tradingstrategy.ai/docs/learn/backtesting.html)
- No India-specific point-in-time fundamentals source (e.g. historical ROE as-reported) was found in this session.

### Inferences
- **Invalidation price:** Three options, preregister one as primary and report the others:
  1. *Disabled:* set `invalidation_price=None` and `thesis_text="INTACT"` for all dates. Isolates the technical/cap logic. Simplest and fully point-in-time.
  2. *Cost-relative proxy:* invalidation = average cost basis as of date t times (1 - d), with d preregistered (e.g. 0.25), using cost basis reconstructed from trades up to t. Fully point-in-time if cost is.
  3. *Market-relative proxy:* invalidation = 52-week low as of t, or 200-DMA times (1 - d). Point-in-time.
  Using the 2026 values (even scaled) is forbidden: the user chose them knowing 2024-2026 prices.
- **Conviction:** The 2026 conviction scores also embed hindsight (holdings that went up may have been upgraded). Run (a) conviction fixed at a neutral constant (e.g. 4 for all, so the conviction gate is non-binding) and (b) conviction = 3 for all (gate always binding), and report how many decisions change. Do not use current per-stock conviction as primary.
- **Fundamentals (ROE):** Pass `roe` such that `fundamental_unknown` is not triggered uniformly; simplest is to pass a constant value >= `minimum_roe` (gate disabled), and state the REVIEW path is untested. Do not use current ROE.
- **total_return input:** Must be computed from cost basis as of t (FIFO or average cost from trades.csv dated <= t) and price at t, not current cost.
- **Universe / survivorship:** Build the universe at each date as the set of symbols held on that date per trades.csv (holdings reconstruction). Symbols sold before 2026 must be included with their historical prices; symbols bought after t must be excluded at t. A secondary run using the fixed current 34-symbol universe is permitted but must be labelled "hindsight universe". If a symbol was delisted/merged, use the last traded price plus deal consideration; flag missing data rather than dropping silently.
- **Prices and corporate actions:** Indicators (50/200-DMA, ATR, 52-week high) computed on split/bonus-adjusted prices so levels are continuous. Dividend adjustment is used only for forward returns (or not at all, consistent with the benchmark choice in section 1). Important subtlety: yfinance back-adjusts the whole history with information from later corporate actions; this rescales levels but does not change ratios like price/DMA, so signals are unaffected, but any absolute-level input (invalidation price, cost basis) must be expressed in the same adjustment basis as the price series (adjust historical cost basis by subsequent split/bonus factors, or use unadjusted prices for both).
- **Indicator warm-up:** 200-DMA and 52-week high need >= 252 trading days before the first decision date (data from ~Oct 2022). Symbols with insufficient history at t yield NO DATA and are excluded from scoring (and counted).
- **Horizon availability:** As of 2026-10-14, a decision made on a late Oct 2025 date has its 252-trading-day horizon ending around mid/late Oct 2026; verify the endpoint exists. Any decision whose t+1 execution plus 252 trading days exceeds the last available close is "unresolved" and excluded, never scored on a truncated window.
- **Data timestamp audit:** Assert in code that every input row used at t has date <= t (unit test with a poisoned future value that would change the decision if leaked).

## 5. Tuning protocol for a short sample (purged/embargoed split, small preregistered grid, DSR/PBO, acceptance rule)

### Takeaway
With ~2 independent years, parameter tuning is close to impossible without overfitting. If any tuning is done: split by decision date, purge any training decision whose 12-month label window overlaps the test period, add an embargo, keep a tiny preregistered grid (<= ~10 configs), evaluate on date-level statistics, and accept a change only if it beats the current parameters out-of-sample, survives a deflated-Sharpe/PBO-style penalty for the number of trials, and makes economic sense. Default outcome: do not change parameters on this sample.

### Cited Findings
- Labels built from forward windows overlap across neighbouring rows; ordinary CV leaks via this overlap. Purging removes training observations whose label windows overlap test label windows; an embargo removes training observations immediately after the test block to handle residual serial correlation — [temporalcv Financial CV docs](https://temporalcv.readthedocs.io/en/latest/api/cv_financial.html); [LuxAlgo purged CV](https://www.luxalgo.com/library/concept/purged-cross-validation/); [eslazarev purged-cross-validation](https://github.com/eslazarev/purged-cross-validation)
- Method attributed to López de Prado, Advances in Financial Machine Learning (2018); the combinatorial purged CV (CPCV) variant yields multiple backtest paths; scikit-learn lacks purging/embargo — [temporalcv example 06](https://temporalcv.readthedocs.io/en/latest/auto_examples/06_financial_cv.html)
- Embargo parameterization varies by implementation (e.g. fraction of total samples after each test fold) — [wraquant preprocessing source](https://wraquant.readthedocs.io/en/stable/_modules/wraquant/ml/preprocessing.html)
- Deflated Sharpe Ratio (Bailey and López de Prado, JPM 2014) corrects for selection bias under multiple testing and non-normal returns; not controlling for the number of trials leads to over-optimistic performance expectations — [SSRN 2460551](https://papers.ssrn.com/abstract=2460551); [CXO Advisory summary](https://cxoadvisory.com/big-ideas/sharper-sharpe-ratio)
- DSR is a probability that the true Sharpe exceeds a benchmark Sharpe that depends on the number of trials, the variance of trial Sharpes, and return skewness/kurtosis; the number of independent trials should be estimated (e.g. via clustering) because trials are correlated — [Wikipedia, Deflated Sharpe ratio](https://en.wikipedia.org/wiki/Deflated_Sharpe_ratio) (from search summary; page not fetchable); [MetricGate (secondary; verify formula against paper)](https://metricgate.com/docs/deflated-johnson-sharpe-ratio/)
- DSR cannot correct biases that affect all configurations uniformly — [arXiv 2507.07107](https://arxiv.org/pdf/2507.07107)
- Probability of Backtest Overfitting (Bailey, Borwein, López de Prado, Zhu, J. Computational Finance 2017) is estimated with combinatorially symmetric cross-validation (CSCV), a model-free nonparametric approach; the authors argue hold-out validation is unreliable for investment backtests — [SSRN 2326253](https://papers.ssrn.com/abstract=2326253); [eScholarship PDF](https://escholarship.org/content/qt4w1110bb/qt4w1110bb.pdf); R implementation `pbo` — [CRAN pbo README](https://ftp.fau.de/cran/web/packages/pbo/readme/README.html)
- Harvey, Liu and Zhu argue that given extensive data mining a new factor should clear a t-ratio above 3.0 rather than 2.0 — [NBER w20592](https://www.nber.org/papers/w20592); published RFS 29(1):5-68 — [SSRN 2513152](https://papers.ssrn.com/abstract=2513152). A 2022 re-examination argues false discovery rates are lower than HLZ imply — [arXiv 2206.15365](https://arxiv.org/pdf/2206.15365)

### Inferences
- **Purge/embargo arithmetic for this sample:** Decision dates t1..t25 (monthly). If test = dates in [T0, T1], every training date t with t + 12 months > T0 (label ends inside test) must be purged; with an embargo of 12 months after T1 as well (labels from dates within 12 months after the test window start inside the test outcome period). Splitting Oct 2023-Sep 2024 train vs Oct 2024-Oct 2025 test with a 12-month purge removes essentially all of training. Practical consequence: a single split of a 25-date sample cannot be both purged and non-trivial. Options: (a) extend the decision-date range back (e.g. Oct 2019 onward) using a pure-technical engine variant (invalidation/conviction/ROE disabled) so that training uses 2019-2022 and testing uses 2023-2025 with a 12-month gap; (b) treat the whole Oct 2023-Oct 2025 sample as a single out-of-sample *validation* of the current preset parameters with no tuning at all. Recommendation: (b) as primary, (a) only if tuning is desired.
- **Preregistered grid (if tuning):** At most ~3 parameters x 2-3 values (e.g. `trailing_stop_atr_multiple` in {2, 3, 4}; `overextension_multiple` in {1.15, 1.20, 1.25}; total-return-for-dip-buy threshold in {15, 25}). Freeze the grid, the objective (date-level mean signed XR or IC), and the acceptance rule in a committed file before running. Count every configuration evaluated (including exploratory ones) as a trial N for DSR.
- **Applying DSR/PBO here:** Compute the objective series per configuration at the date level (25 overlapping monthly observations, or the daily A-minus-B shadow-portfolio return series). PBO via CSCV: split the T dates into S even blocks (S = 4 or 6 given T ~25; S must be even), form all C(S, S/2) train/test combinations, record how often the in-sample best configuration ranks below the median out-of-sample; PBO > 0.5 means selection is worse than random. Overlap between label windows makes blocks dependent, so PBO is optimistic here; state that. DSR with N = number of trials, using skew/kurtosis of the daily active-return series.
- **Acceptance rule for a parameter change (all must hold):** (1) out-of-sample (purged) objective improves vs incumbent with NW lag-11 t > 3.0 or block-bootstrap CI excluding zero on the *difference*; (2) DSR > 0.95 for the chosen configuration; (3) PBO < 0.2 (stricter than 0.5 because of short sample); (4) improvement present in both the rally and the correction regime (section 6); (5) a written economic rationale for why the parameter should generalize. If any fails, keep incumbent parameters.

## 6. Regime caveat: Indian market path Oct 2023 to Oct 2026 and regime-dependent reporting

### Takeaway
The 1-year outcome windows span a strong rally into a late-Sep 2024 peak, a ~16-17% Nifty drawdown into early 2025, a recovery to a new high in early January 2026, and a further roughly 8% drawdown by end-July 2026, with mid/small caps behaving differently. Results will be dominated by 2-3 market phases, so all statistics must be reported by regime and the conclusion stated as conditional on this path.

### Cited Findings
- Nifty 50 reached an all-time high of 26,277 around Sept 26-27, 2024 — [Daily Pioneer](https://dailypioneer.com/news/lessons-from-nifty-50-crash-every-investor-must-know); [Business Standard](https://www.business-standard.com/amp/markets/news/nifty-fall-since-october-2nd-biggest-in-10-years-16-stocks-tank-over-20-125012800225_1.html)
- The subsequent fall was about 16% by March 4, 2025 per one source, about 17.3% peak-to-trough to ~21,743 per another; sources differ on exact numbers — [Daily Pioneer](https://dailypioneer.com/news/lessons-from-nifty-50-crash-every-investor-must-know); [One Trade Journal](https://onetradejournal.com/glossary/market-correction)
- Business Standard called the fall since Oct 2024 the second biggest in 10 years excluding Covid, with 16 Nifty stocks down over 20% — [Business Standard](https://www.business-standard.com/amp/markets/news/nifty-fall-since-october-2nd-biggest-in-10-years-16-stocks-tank-over-20-125012800225_1.html)
- Nifty made a record high of 26,329 on January 2, 2026, closed July 31, 2026 at 24,384 (needing ~8% to regain the peak), while the Nifty Midcap 150 was within 0.14% of its July 21, 2026 record — [Cafemutual / Abakkus MF](https://cafemutual.com/news/industry/38496-nifty-50-needs-8-gain-to-reclaim-its-peak-abakkus-mutual-fund)
- Over the past 35 years, 5-10% Nifty corrections occurred 27 times and 10-20% corrections 13 times — [Cafemutual / Abakkus MF](https://cafemutual.com/news/industry/38496-nifty-50-needs-8-gain-to-reclaim-its-peak-abakkus-mutual-fund)
- Market levels for Aug-Oct 2026 were not found in this session.

### Inferences
- **Regime labelling (preregistered, mechanical):** Label each decision date by benchmark state at t (Nifty TRI above/below its 200-DMA; or drawdown from running peak > 10%) and, separately, label each outcome window by the benchmark's forward 1-year return (up/flat/down terciles across the sample). Report every headline metric split by regime, with counts.
- **Expected mechanical bias:** A trend-following engine (SELL below 200-DMA, ACCUMULATE when above both DMAs) tends to look good when outcome windows cover a sustained trend and poorly around V-shaped reversals; decisions dated Oct 2024-Mar 2025 (BEARISH signals near the trough) then scored through a 2025 recovery are the key stress case. Report SELL decisions made during the drawdown separately.
- **Large vs mid/small:** Holdings likely include mid/small caps; their 2024-2026 path diverged from Nifty 50 (Midcap 150 near record by July 2026 while Nifty 50 was ~8% below). Excess returns vs Nifty 50 then partly measure size/style exposure, not decision skill. Add a secondary benchmark (Nifty 500 TRI or a size-matched index) and report decision skill net of that.
- **Statement of conclusion:** "Over one partial market cycle (two non-overlapping years), the engine's decisions showed X; this is not evidence of generalizable skill" unless the section 2/5 thresholds are cleared in every regime.

### Gaps
- Nifty 50 levels for Aug-Oct 2026 and exact trough dates/levels need to be pulled from NSE data rather than news sources.
- Midcap/smallcap index paths for 2024-2025 not retrieved.

## Design spec for the prompt

Numbered, testable requirements for the hindcast implementation.

1. **Decision dates:** Generate one decision date per month from Oct 2023 to Oct 2025 inclusive, using the last NSE trading day of each month on or before the nominal date; persist the list. Test: list length and that every date is an NSE trading day.
2. **Point-in-time data cut:** For each decision date t, all inputs (prices, DMAs, ATR, 52-week high, cost basis, holdings, weights) use only rows dated <= t. Test: a unit test injects a poisoned price at t+1 and asserts the decision at t is unchanged.
3. **Warm-up:** Price history starts at least 260 trading days before the first decision date; symbols lacking 200 days of history at t get NO DATA and are excluded from scoring but counted. Test: report includes per-date coverage counts.
4. **Score the `decision` field**, not the `signal` emoji field; record both. Classes scored: SELL, TRIM, HOLD, ACCUMULATE, BUY. NO DATA / VERIFY DATA / NO THESIS are excluded from accuracy and reported as a coverage table.
5. **Invalidation price:** Primary run uses `invalidation_price=None` (disabled). Secondary runs use preregistered point-in-time proxies (cost basis at t x (1 - 0.25); 52-week low at t). The 2026 `thesis.csv` Invalidation_Price values are never used. Test: assert no value from thesis.csv Invalidation_Price is read in the hindcast path.
6. **Conviction:** Primary run uses a constant conviction (4) for every symbol; sensitivity run uses 3. Current per-stock conviction is not used. Report count of decisions that change between the two.
7. **Fundamentals:** ROE gate disabled by passing a constant ROE >= `minimum_roe`; report states the REVIEW/ROE path is untested.
8. **Cost basis and total_return:** Reconstructed from trades.csv with trade date <= t (average-cost method, documented), in the same split/bonus adjustment basis as the price series. Test: for a symbol with a known split, total_return at t is identical whether computed from adjusted or unadjusted series.
9. **Universe:** Primary universe at t = symbols held at t per reconstructed holdings (includes later-sold symbols, excludes later-bought ones). Secondary run on the fixed current universe labelled "hindsight universe". Test: a symbol bought after t never appears at t.
10. **Weights and caps:** Position, sector and risk-group weights passed to the engine are computed from the simulated portfolio at t (shadow-portfolio run) or the reconstructed real holdings at t (decision-scoring run); never from the current portfolio.
11. **Forward horizon:** Outcome measured from close of t+1 (execution day) to close of t+1+252 trading days. Decisions whose horizon end exceeds the last available close are marked UNRESOLVED and excluded. Test: no scored decision has a truncated window.
12. **Benchmark:** Nifty 50 TRI (gross); if unavailable, a Nifty 50 ETF's dividend-adjusted close, with the substitution logged. Stock forward returns use the same dividend convention as the benchmark. Test: an assertion compares conventions (both adjusted or both price-only).
13. **Excess return:** XR = (1+R_stock)/(1+R_bench) - 1 as primary; arithmetic difference reported as secondary.
14. **Correctness rules:** With preregistered band b (primary: b = 5%, sensitivity at 0% and 2%): SELL and TRIM correct if XR < -b, wrong if XR > +b; ACCUMULATE/BUY correct if XR > +b, wrong if XR < -b; otherwise neutral. HOLD is not scored for direction; report its XR distribution as the base rate and the share with |XR| <= 10%. Hit rates exclude neutrals in the denominator and the neutral share is reported.
15. **Signed-score payoff:** Map SELL = -2, TRIM = -1, HOLD = 0, ACCUMULATE/BUY = +1; report mean of score x XR per date and overall.
16. **Information coefficient:** Per date, Spearman and Kendall tau-b between signed score and XR; report mean IC, share of dates with IC > 0, and NW (lag 11) t-stat.
17. **Episodes:** Collapse consecutive identical decisions per symbol into episodes; report all accuracy statistics at decision level and episode level (scored at episode start).
18. **Inference unit = date:** Every significance test is performed on the per-date cross-sectional statistic series, using Newey-West HAC with lag 11 (Bartlett) as primary, Hansen-Hodrick lag 11 as secondary (fallback to NW if variance negative), and a moving-block bootstrap over dates (block length 12, 10,000 resamples, fixed seed).
19. **Effective sample size:** Report n_raw, n_episodes, n_eff_time = n_dates / (2h/3) with h = 12, and cross-sectional design effect 1 + (m-1)*rho_hat using the measured average pairwise correlation of 1-year XR. Wilson 95% intervals reported on both raw n (labelled naive) and n_eff.
20. **Evidence threshold:** A decision class is declared "evidence of skill" only if its episode-level effect has the correct sign, NW t > 3.0 or bootstrap 95% CI excludes zero, it has >= 10 independent episodes, and the sign holds in every regime bucket. Otherwise the report must say "insufficient evidence".
21. **Shadow portfolios:** (A) follow-model, (B) do-nothing buy-and-hold of the holdings at the first date, (C) Nifty 50 TRI, (D) optional equal-weight monthly rebalance. Trades execute at t+1 close. SELL = exit 100%; TRIM = sell 50% (trailing stop) or down to max_position_pct (cap breach); ACCUMULATE = add 1% of NAV from cash, capped at max_position_pct, scaled pro rata if cash is short; no leverage, no external flows.
22. **Cash:** Cash earns 0% in the primary run and a preregistered money-market rate in a sensitivity run; a third variant parks SELL/TRIM proceeds in the benchmark ETF.
23. **Portfolio metrics:** CAGR, annualized volatility, max drawdown and its duration, turnover, trade count, and the A-minus-B daily active-return series with overlap-aware CI. All portfolios start from the same NAV on the same date.
24. **Corporate actions:** Indicators computed on split/bonus-adjusted prices; delisted/merged symbols use last price plus deal consideration and are flagged; no silent drops (test: count of symbols in = count scored + count excluded with reason).
25. **No tuning in the primary run:** The Oct 2023-Oct 2025 run uses the current RISK_CONFIG unchanged and is labelled out-of-sample validation of current parameters.
26. **If tuning is attempted:** Grid of <= 10 configurations committed to a file before the run; train/test split by decision date with a 12-month purge and 12-month embargo (or extend decision dates back to 2019 with a technical-only engine); every evaluated configuration counted as a trial; report DSR (N = trials) and PBO via CSCV (S = 4 or 6 blocks); accept a change only if OOS improvement NW t > 3.0, DSR > 0.95, PBO < 0.2, improvement holds in both rally and correction regimes, and a written economic rationale exists.
27. **Regime reporting:** Label each date by benchmark above/below 200-DMA and by drawdown > 10% from peak; label each outcome window by benchmark forward-return tercile; report every headline metric by regime, and separately for SELL decisions made Oct 2024-Mar 2025.
28. **Secondary benchmark:** Repeat XR scoring vs Nifty 500 TRI (or a size-matched index) to separate size/style exposure from decision skill.
29. **Reproducibility:** Data snapshot hash, config, random seed, and code commit recorded in the report header; rerun produces identical outputs.
30. **Mandatory caveat block:** Report states: costs and taxes excluded; ~2 non-overlapping years of outcomes; invalidation/conviction/ROE not point-in-time and therefore disabled or proxied; results conditional on the Oct 2023-Oct 2026 market path.
